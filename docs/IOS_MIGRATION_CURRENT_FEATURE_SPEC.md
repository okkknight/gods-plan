# God's Plan 当前版本功能基线

> 用途：作为后续原生 iOS 版本迁移、行为对齐和验收的基线。
>
> 规则：本文以当前可运行代码和实际数据为准；如果旧产品文档与本文或代码冲突，以当前代码为准。

## 1. 产品定位

God's Plan 是一个本地单用户英语口语学习与复习应用。当前内容为《Modern Family》Season 1 的 S01E01–S01E24，共 24 篇课程。

用户每天打开应用后，可以查看今天需要学习的课程、需要复习的课程和当天已经完成的课程。课程支持中文、英文标准版和 Cue Version 三种阅读模式；英文模式支持朗读音频、分段字幕、字幕高亮、点击跳转和循环播放。

当前版本没有账号系统、云同步、AI 课程生成、录音或发音评分。

## 2. 全局规则

### 2.1 用户与存储

- 当前是单用户应用。
- 不需要注册、登录或密码。
- 不区分用户。
- 数据默认保存在 `data/english-learning.db`。
- 数据库使用 SQLite 和 Drizzle。
- 不支持云同步、多设备同步或账号恢复。

### 2.2 业务日期

- 默认时区为 `Asia/Shanghai`。
- 业务日期格式为 `YYYY-MM-DD`。
- “今天”按应用时区计算，不能直接从 UTC ISO 字符串截取。
- 当前日期工具名为 `addBusinessDays`，但实际按自然日加减，周末不会跳过。

### 2.3 课程顺序和状态

课程按 `orderIndex` 排序，当前顺序为 S01E01 到 S01E24。

课程状态：

- `queued`：尚未开始。
- `active`：已经开始，存在当前待复习阶段。
- `completed`：完成全部复习阶段。
- `archived`：已归档，不参与学习计划。

归档时保存归档前状态，取消归档时恢复原状态。

## 3. 复习调度

### 3.1 阶段和日期

每门课程有 6 个阶段：

| 阶段 | 标签 | 累计偏移 |
| --- | --- | ---: |
| 0 | 首次学习 | 0 天 |
| 1 | 第 1 次复习 | 1 天 |
| 2 | 第 2 次复习 | 3 天 |
| 3 | 第 3 次复习 | 7 天 |
| 4 | 第 4 次复习 | 15 天 |
| 5 | 第 5 次复习 | 30 天 |

阶段间隔为 `1 / 2 / 4 / 8 / 15` 天。

课程只保存当前待完成阶段和当前应完成日期，不预先写入未来所有任务。

完成当前阶段后，下一阶段日期从实际完成日期重新计算。例如第 1 阶段在 8 月 4 日完成，第 2 阶段安排在 8 月 6 日。

### 3.2 新课

- 每天最多解锁一篇新课。
- 按课程 `orderIndex` 顺序解锁。
- 当前最早的 queued 课程未完成时，下一篇不会解锁。
- 未完成的新课第二天仍然是当前新课。
- 新课完成当天不会再展示另一篇新课。
- 新课不会阻塞其他已开始课程的复习。
- 如果复习积压超过 2 条，则不展示新课。

### 3.3 复习显示

内部区分：

- 逾期复习：计划日期早于今天。
- 今日复习：计划日期等于今天。

当前用户界面不显示“逾期”字样，而是将逾期和今日到期任务合并显示为“今日复习”。

- 复习任务按原计划日期从早到晚排序。
- 页面最多展示 3 条复习任务。
- 内部复习积压数量不受 3 条显示上限影响。
- 新课是否暂停依据全部积压数量判断。
- 空的任务分组不显示。

### 3.4 完成任务

只有今天的任务可以完成。服务端提交时会重新检查：

- 课程存在。
- 课程未归档。
- 页面提交的阶段仍是数据库当前阶段。
- 课程已经到期，而不是未来任务。
- 当前任务没有被其他操作改变。

完成后，在一个事务中：

1. 写入学习事件。
2. 记录原计划日期和实际完成日期。
3. 计算下一阶段和下一次日期。
4. 更新课程状态和进度。

完成第 5 次复习后，课程状态变为 `completed`，并删除当前进度记录，但保留全部学习事件。

### 3.5 撤销完成

- 只能撤销今天完成的任务。
- 只能撤销该课程最新的一条完成记录。
- 过去完成记录不能撤销。
- 撤销后没有历史事件时，课程恢复为 `queued`。
- 撤销后仍有历史事件时，恢复到被撤销前的当前阶段和原计划日期。
- 撤销不会删除其他历史学习事件。

## 4. Today 页面

路径：`/today`

页面顶部显示：

- 上海时区下的完整中文日期。
- 标题“今天学什么”。
- “已完成数量 / 今日任务总数”。
- “今日完成”说明。

页面分组：

### 4.1 今日复习

只有存在复习任务时显示。每张任务卡显示：

- 集数，例如 `S01E01`。
- 课程标题。
- “今日复习”状态标签。
- 当前阶段标签。
- “开始练习”按钮。

点击卡片主体或按钮都进入课程阅读页。

### 4.2 今日新学

只有满足新课规则时显示。显示：

- 下一篇 queued 课程。
- “今日新课”状态标签。
- “首次学习”阶段。
- “开始练习”按钮。

### 4.3 今日已完成

只有当天完成过任务时显示。显示：

- 课程信息。
- “今天已完成”状态标签。
- 已完成阶段。
- “查看课程”按钮。
- “撤销完成”按钮。

### 4.4 空状态

如果今天没有任何任务，显示“今天没有学习任务。”

### 4.5 日期导航

页面底部提供：

- 前一天。
- 当前日期。
- 后一天。
- 非今天日期下的“回到今天”。

过去日期显示真实记录，未来日期显示预计计划，只有今天可操作。

## 5. Calendar 页面

路径：`/calendar`

页面提供日期选择器，当前输入范围为 `2020-01-01` 至 `2030-12-31`。

### 5.1 过去日期

显示当天真实学习事件：

- 阶段。
- 课程标题。
- 原计划日期。
- 实际完成日期。

没有记录时显示“这一天没有完成记录。”过去日期不能完成或撤销任务。

### 5.2 今天

显示今日复习、今日新学、今日已完成三个分组，行为与 Today 页面一致，可以完成或撤销。

### 5.3 未来日期

显示基于当前进度生成的预计任务，并提示：

> 以下为基于当前学习进度生成的预计计划。如果当前任务延期完成，未来安排会自动变化。

未来任务显示阶段、课程标题和“预计新课”或“预计复习”。未来预测不写数据库、不产生学习事件、不显示完成按钮。预测范围最多为未来 180 天。

## 6. Course Reader 页面

路径：`/course/[id]`

顶部显示：

- “返回今日”。
- 课程集数。
- 当前学习阶段。
- 课程标题。

### 6.1 模式切换

默认模式为中文，模式为：

- 中文。
- 英文。
- Cue。

切换模式不刷新页面。音频元素持续挂载，切换到中文或 Cue 时只隐藏音频控件，切回英文时恢复显示，播放不会因为模式切换被切断。

### 6.2 中文模式

- 显示“中文剧情描述”标题。
- 显示中文剧情文本。
- 保留原始换行。
- 使用适合连续阅读的较大字号。

### 6.3 英文模式

- 显示“Spoken English 标准版”标题。
- 显示英文内容。
- 使用衬线字体。
- 有可用音频和 manifest 时，按音频分段显示英文字幕。
- 没有可用音频时，显示普通英文正文。

### 6.4 Cue 模式

Cue 内容使用轻量 Markdown 渲染，支持：

- 一级至六级标题。
- 无序列表。
- 粗体。
- 斜体。
- 行内代码。
- 链接。
- 分隔线。
- ASCII 连续下划线和全角连续下划线填空。

填空显示为带颜色的下划线，并带有“填空”无障碍标签。

### 6.5 完成按钮

只有 URL 中的日期等于今天，且课程状态为 queued 或 active 时显示“完成本次学习”。

点击后：

- 按钮显示“处理中…”。
- 调用完成接口。
- 成功后回到 `/today`。
- 失败时在按钮下显示错误信息。

过去、未来或普通预览页面不显示完成按钮。

## 7. 英文音频和字幕

当前 24 门课程均有 `english.wav` 和 `manifest.json`，路径为：

```text
public/audio/courses/{course-slug}/
```

### 7.1 音频控件

英文模式使用浏览器原生音频控件，支持播放、暂停、拖动、时长和音量控制。

### 7.2 播放模式

支持：

- 单篇播放。
- 循环播放。

播放模式按钮使用 Repeat 1 和 Repeat 图标，并提供无障碍状态说明。

### 7.3 分段字幕

manifest 的每个分段包含：

- 序号。
- 英文文本。
- `start`。
- `end`。
- `duration`。

不同课程的分段数量可以不同。当前例如 S01E01 有 12 段，S01E02 有 13 段。

### 7.4 同步和点击跳转

播放时根据 `currentTime` 匹配当前分段：

- 当前分段高亮。
- 自动滚动到视口中间。
- 点击分段后跳转到该段开头。
- 点击分段后立即开始播放。

## 8. 课程库

路径：`/library`

### 8.1 列表

页面显示：

- 课程总数。
- 参与计划的课程数量。
- 集数。
- 标题。
- 当前状态或阶段。
- 下次复习日期。
- 预览按钮。
- 归档或取消归档按钮。

归档课程仍出现在课程库中，但不参与计划。

### 8.2 导入新课程

导入流程：

1. 选择“新课程”。
2. 选择 JSON 文件。
3. 浏览器读取文件。
4. 服务端使用 Zod 校验。
5. 事务写入课程、section 和 paragraph。
6. 刷新课程库。

重复 slug 在新课程模式下报错，提示使用更新模式。

### 8.3 更新已有课程

更新模式会更新课程元信息和内容，但必须保留：

- 原课程 ID。
- 课程状态。
- 当前进度。
- 下次到期日期。
- 学习事件。

旧 section 和 paragraph 会被替换为新内容。

### 8.4 归档

归档不会删除课程、内容、进度或历史事件，只会让课程退出学习调度。取消归档后恢复归档前状态。

## 9. 课程内容和数据模型

原始课程 Markdown 位于：

```text
docs/Modern_Family_S1E01-E24_Speaking_Course_MD/episodes/
```

标准 JSON 位于：

```text
content/courses/
```

每门课程包含：

- `schemaVersion`
- `slug`
- `series`
- `season`
- `episode`
- `title`
- `orderIndex`
- `sections`

当前有三个 section：

- `chinese`
- `english`
- `cue`

每个 section 当前包含一个对齐 paragraph，保存中文、英文和 Cue 三份内容。

数据库主要表：

- `courses`：课程和状态。
- `course_sections`：课程模式 section。
- `course_paragraphs`：中文、英文和 Cue 内容。
- `course_progress`：每门课程当前唯一待完成阶段。
- `study_events`：每个阶段的完成历史。

## 10. API 行为

### 完成

```text
POST /api/complete
```

请求字段：`courseId`、`expectedStage`。

### 撤销

```text
POST /api/undo
```

请求字段：`courseId`。

### 导入

```text
POST /api/import
```

请求字段：`course`、`mode`，其中 mode 为 `create` 或 `update`。

### 归档

```text
POST /api/archive
```

请求字段：`courseId`、`action`，其中 action 为 `archive` 或 `unarchive`。

所有写入操作需要在服务端重新校验，并使用数据库事务。

## 11. 当前明确不包含

- 云同步和多设备同步。
- AI 自动生成课程。
- 应用内大模型 API。
- 录音、麦克风、语音识别和发音评分。
- 跟读检测。
- 单词本和生词管理。
- 积分、签到、连续学习天数和排行榜。
- 社交功能。
- 复杂统计图表。
- 自定义复习曲线。
- 删除或修改过去完成记录。
- 自动备份。
- PWA 和离线模式。

## 12. iOS 迁移必须保持的行为

以下行为属于当前版本的兼容性要求：


- 复习阶段仍为 0、1、2、3、4、5。
- 日期偏移仍为 0、1、3、7、15、30。
- 下一次复习从实际完成日期计算。
- 每门课程只保存一个当前待完成阶段。
- 每天最多一篇新课。
- 复习积压超过 2 条时暂停新课。
- 页面最多展示 3 条复习任务。
- 只有今天可以完成或撤销。
- 过去日期显示事实，未来日期显示预测。
- 未来预测不写入学习历史。
- 更新课程内容不能丢失进度和学习事件。
- 归档不能删除课程数据。
- 中文、英文、Cue 必须保持同一课程下的对应关系。
- 英文音频和字幕时间轴必须保持一致。
- 单篇播放、循环播放、字幕高亮和点击跳转必须保留。
- 当前版本不自动增加账号、同步、录音或发音评分能力。

## 13. Web 与 iOS 的隔离和发布边界

iOS 迁移必须是与现有 Web 版本并行的独立产品工程，不能以迁移为理由修改、替换或破坏当前 Web 功能。

### 13.1 代码和工程隔离

- iOS 使用独立的 Xcode / Swift 工程或独立原生仓库。
- 不把 Swift、Xcode 工程、DerivedData、Swift Package 构建产物加入 Web 工程的运行目录。
- 不直接修改 Web 的页面、API、数据库 schema、课程 JSON、音频文件或部署配置来服务 iOS。
- 如果需要抽取共享规则，应复制并验证行为，或建立明确的独立共享协议；不能直接耦合 Web 运行时。
- Web 的现有 Git 历史、分支和未完成工作必须保持不变。

### 13.2 数据和运行时隔离

- Web 继续使用现有 SQLite 和 VPS 运行实例。
- iOS 的本地存储、迁移数据和缓存使用 iOS 自己的存储边界。
- iOS 开发、测试和发布不能改写 Web 的 `data/english-learning.db`。
- iOS 的测试必须使用 fixture、临时数据库或独立测试数据，不能污染 Web 的默认数据库。
- 如果未来增加同步服务，必须先定义协议、冲突策略和上线迁移方案，不能隐式改变当前 Web 的单用户行为。

### 13.3 发布和部署隔离

- Web 保持独立构建、独立测试、独立部署和独立回滚。
- iOS 保持独立的 Xcode archive、签名、TestFlight 和 App Store 发布流程。
- Web 发布不应要求先构建或发布 iOS。
- iOS 发布不应要求先部署 Web。
- 不把 iOS 构建产物同步到 Web VPS。
- 不改变现有 `godsplan.service`、Caddy `/godsplan` 路由或 Web 的生产目录。
- 两端应分别记录版本号、提交、构建证据和发布结果。

### 13.4 变更和验收边界

- Web 功能修复只能由 Web 变更负责，不通过 iOS 迁移顺带修改。
- iOS 功能变更只能由 iOS 工程负责，不应为了方便修改 Web 行为基线。
- 任何共享内容或规则变更都必须分别验证 Web 和 iOS 的结果。
- Web 发布验收至少覆盖现有 Web 测试、生产构建和公网行为。
- iOS 发布验收至少覆盖原生单元测试、模拟器/真机行为、归档和 App Store 提交所需检查。
- 任一端失败时，只阻断该端发布，不默认阻断另一端的独立发布。

### 13.5 推荐目录边界

当前 Web 仓库继续保持现状；iOS 后续应位于独立目录或独立仓库，例如：

```text
godsplan/       # 当前 Web，继续独立发布
godsplan-ios/   # 原生 iOS，独立开发、测试和发布
```

具体采用独立仓库还是同一父目录下的独立子目录，属于后续工程决策；无论采用哪种形式，都必须保持独立 Git 历史、独立依赖和独立发布流水线。
